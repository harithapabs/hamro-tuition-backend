# 🚀 Free Deployment Guide

This guide deploys **Hamro Tuition** to production for **$0/month** using:
- **Frontend** → Vercel (free, auto-deploy from GitHub)
- **Backend** → Render (free tier, sleeps after 15min inactivity)
- **Database** → NeDB (built into the project, persists on Render's disk)
- **Files** → local `uploads/` folder (persists on Render)

> ⚠️ **Free tier limitations:**
> - Render free tier **spins down after 15min of no traffic** → first request takes 30-60s
> - Disk **persists across deploys** but **resets if you change plan or remove the service**
> - For real production, upgrade to Render Starter ($7/mo) or migrate to MongoDB Atlas + Cloudinary

## Step 2: Deploy Backend to Render (3 min)

### Option A: One-click via render.yaml
1. Go to [dashboard.render.com](https://dashboard.render.com) → **New** → **Blueprint**
2. Connect your GitHub repo
3. Render auto-detects `render.yaml` and creates the service
4. Wait for first deploy (~3-5 min)

### Option B: Manual
1. **New** → **Web Service** → connect your repo
2. Configure:
   - **Root Directory**: `backend`
   - **Build Command**: `npm install`
   - **Start Command**: `node server.js`
   - **Plan**: Free
3. Click **Create Web Service**

### Set environment variables (in Render dashboard → Environment):
- `NODE_ENV` = `production` (auto-set by render.yaml)
- `JWT_SECRET` = (auto-generated by render.yaml, or paste your own 32+ char string)
- `ALLOWED_ORIGINS` = `https://your-app.vercel.app` (you'll set this after Step 3)
- *(optional)* `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` for real emails

### ✅ Test:
Visit `https://YOUR-SERVICE.onrender.com/api/health` — should return `{"status":"ok"}`

---

## Step 3: Deploy Frontend to Vercel (2 min)

1. Go to [vercel.com/new](https://vercel.com/new) → import your GitHub repo
2. Configure:
   - **Framework Preset**: Vite
   - **Root Directory**: `frontend` (click "Edit" to set)
   - **Build Command**: `npm run build` (default)
   - **Output Directory**: `dist` (default)
3. **Environment Variables**:
   - `VITE_API_URL` = `https://YOUR-SERVICE.onrender.com/api`
4. Click **Deploy** (~1-2 min)

### ✅ Test:
Visit your Vercel URL — site should load!

---

## Step 4: Connect Frontend ↔ Backend (1 min)

After Vercel deploys, you'll get a URL like `https://hamro-tuition-xyz.vercel.app`.

1. Go back to **Render** → your backend service → **Environment**
2. Update `ALLOWED_ORIGINS` = `https://hamro-tuition-xyz.vercel.app`
3. Save (auto-redeploys, ~1 min)

Now login should work end-to-end.

---

## Step 5: Custom Domain (optional)

- **Vercel**: Project → Settings → Domains → add `yourdomain.com`
- **Render**: Service → Settings → Custom Domain → add `api.yourdomain.com`
- Update `ALLOWED_ORIGINS` in Render to `https://yourdomain.com`
- Update `VITE_API_URL` in Vercel to `https://api.yourdomain.com/api`

## 🆘 Troubleshooting

### "Too many login attempts"
Rate limit hit (10/15min). Wait 15 min or restart backend.

### Login fails with CORS error
- Check `ALLOWED_ORIGINS` in Render matches your Vercel URL **exactly** (no trailing slash, https)
- Check browser Network tab — the CORS preflight OPTIONS should return 200

### Cookie not set
- In dev, cookie works on http://localhost. In production, must be HTTPS (Vercel + Render are HTTPS by default)
- Check `withCredentials: true` is in `frontend/src/utils/api.js` (it is)

### First request is slow
- Render free tier sleeps after 15min → first request wakes it up (~30-60s)
- Upgrade to Starter plan ($7/mo) for always-on

### Data lost after deploy
- Render free tier keeps disk between deploys, but **resets on plan changes or service recreation**
- For guaranteed persistence, upgrade to Render Starter or migrate to MongoDB Atlas
